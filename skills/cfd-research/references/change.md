# 受控修改

1. 把意图落到具体实体（如入口面法向速度、截面均速、模板参数或时间函数幅值）。记录当前值、单位、源文件和生效位置。若已有未提交修改，用当前工作状态作基线。识别生成脚本或共享 include 的其他消费者，判断改动一处会影响哪些算例。
2. 按用户要求原地修改或生成独立工况。改前对参与求解和后处理的输入建立快照（包括未跟踪输入、网格及外部引用）；大文件可取摘要。保留用户的并行修改。能以专用覆盖项隔离共享参数时，优先局部化改动。修改重启输入时确认所选启动时刻实际读它。
3. 区分三类影响：
   - 与同一物理输入等价的重复表示，例如分区输入或生成后的同一速度；只在确认确实被使用且符合本次授权时同步，并写出理由。
   - 自动派生的量，例如定 ν、L 下的 Re，定步长和网格下的入口 Co 尺度。计算前后值。局部峰值和全域稳定性通常要运行后判断。
   - 需要研究者决定的约束，例如保持 Re 会改变 ν，保持目标 Co 可能需改 Δt，湍流强度换算可能影响 k，比较系数时 Uref 可以共用也可以随工况变化。保留已指定对照条件，把超出“只改入口”的调整作为待选；若用户已明确指定保持某约束，按其定义落实并展示联动。
4. 改后查看路径清单与行级补丁，重新读取生效值；比较受保护的输入及引用。Git diff 对未跟踪文件或已有编辑不完备，可用下列辅助工具复核指定输入目录的内容、增删与符号链接。将快照存在输入目录之外；外部链接目标与执行环境另行核实。若有意外变化，定位归属，在自己的副本修正再核对。
5. 交付“改前 → 改后、位置、为何改”，附补丁、派生影响、验证覆盖范围。重跑结果应有新的运行标识，历史输出继续归属于原工况。

在技能目录中找到 scripts/input_snapshot.py。示例对仅含输入的 case 目录做核查：

```sh
python3 "$SKILL_DIR/scripts/input_snapshot.py" save case /tmp/before-cfd.json
# 执行授权的编辑
python3 "$SKILL_DIR/scripts/input_snapshot.py" diff case /tmp/before-cfd.json
```

diff 输出 changed/added/removed；还要查看具体键的补丁，因为同文件内也可能误改。网格在外部时单独记录路径、版本与摘要。
